	深色虚线不再影响主要校准链路。

- `0x08`应作为主连续位置源；`0x51`不能与其交替写入同一位置缓存后计算增量，
	否则来源切换会被误认为实际位移。

## 二、发现的问题

### 🔴 严重问题

#### F1: 区块地图曾按错误资料录入

- **证据**: 赛题原始 PDF 图1明确标出 `1~28` 共28个绿色区块。
- **原问题**: 旧版 `_LAYOUT` 缺少27号区块, 多行编号和网格位置也与赛题图不一致。
- **状态**: ✅ **已修复** - `path_plan.py` 已恢复28块、7列×6行布局; `visited[0]` 不再计入任务进度。

#### F2: 颜色跳变检测算法逻辑缺陷 (计划中的原始实现)

- **位置**: 第8.2节 `check_boundary_crossed()` 函数
- **现象**: 计划中的检测逻辑使用单帧 `prev_green_ratio` 对比 `curr`, 防抖计数器在第一帧跳变后因 `prev` 被更新为新值而立即重置
- **影响**: 边界跳变无法通过防抖确认, 导致不可靠的跳变检测
- **修复**: 改用**窗口比较法**: 比较最近N帧 vs 前N帧的绿色占比, 仅当两组窗口颜色一致变为另一组时才触发跳变

**代码中已修正**: `localization.py` 使用 deque 窗口 + 双窗口比较

### 🟡 中等问题

#### M1: 速度档位 `block_timeout` 过于激进

- **位置**: 第 12.1 节速度配置
- **现象**: `competition` 档的 `block_timeout=3秒` 意味每块从检测到撒药完成的窗口仅3秒, 对30cm/s累计移动(可能跨过空缺格子) 极为紧张
- **建议**: `competition` 档将 `block_timeout` 提高到至少5秒, 或根据路径中实际的最大相邻距离动态计算
- **状态**: ✅ **已修复** — `config.py` competition `block_timeout` 已从 3→5 秒

#### M2: 缺失 MCU 端电池电压上报

- **位置**: 第13节异常处理 + 第3节通信协议
- **现象**: 异常处理中有 `read_voltage()` 电池低压检测, 但第3节通信协议仅定义了光流和飞行状态两种回传帧, **未定义电压回传帧**
- **影响**: 无法在树莓派端检测电池低压, 只能在MCU侧依赖预设的电压保护阈值
- **建议**: 在协议中增加电池电压回传帧 (如 `0xCC 0x03 [V_LO V_HI 2B u16 mV]`)
- **状态**: ✅ **已修复** — `lx_protocol.py` 新增 `parse_battery_voltage()`, `mcu_serial.py` 新增 `_parse_buffer()` 0x03 帧处理, `read_voltage()` 已实现

#### M3: MCU 心跳缺失

- **位置**: 第15节风险R9
- **现象**: 计划提到"MCU侧检测心跳超时→自动触发紧急降落", 但第3节通信协议未定义树莓派→MCU的心跳机制
- **建议**: 增加定期心跳帧 (如 `0xBB 0x04` 每500ms), MCU侧若2秒无心跳则自动触发紧急降落
- **状态**: ✅ **已修复** — `lx_protocol.py` 新增 `build_heartbeat_query()`, `mcu_serial.py` 新增 `send_heartbeat()`, `main.py` 主循环每 500ms 发送心跳

#### M4: AUX2/CH6 通道值获取未实现

- **位置**: 第10.3节 `_check_start_signal()`
- **现象**: 状态机启动依赖 `mcu.read_aux2() > 1700`, 但通信协议未定义CH6值的回传方式
- **建议**: 在飞行状态帧中增加CH6/CH7字段, 或增加独立查询帧

### 🟢 轻微问题

#### L1: 路径 11→10 和 9→8 跳过了空缺格子

- **位置**: 第9.2节 PATH
- **现象**: PATH 中区块11(Col3,Row2) 跳转到 10(Col0,Row3), 跳过中间的3个空列。这在实际飞行中是合法的蛇形策略, 但需要确认移动距离不超过安全边界
- **影响**: 移动距离约165cm (3.3个格子), 在光流定位下可能产生累积误差

#### L2: OCR 依赖 tesseract 的准确率

- **位置**: 第7.3节
- **现象**: 仅使用 `cv2.threshold` 做简单二值化后 OCR, 无图像预处理(倾斜校正/尺寸归一化)
- **建议**: 增加透视变换、自适应阈值、形态学去噪等预处理步骤

#### L3: `cmd_ascend(0, 0)` 作为悬停指令

- **位置**: 第13节 `handle_lost_optical_flow()`
- **现象**: 使用 `cmd_ascend(0, 0)` 作为悬停指令, 但该函数的 speed 参数下限为 10 (第4.3节定义), 发送 speed=0 的行为未定义
- **建议**: 确认凌霄IMU是否支持 speed=0 的悬停, 或改用专门的悬停API指令
