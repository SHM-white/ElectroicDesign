# 任务委派技能

此技能旨在帮助主模型（MiMo-V2.5-Pro）更好地利用不同模型的子代理（如DeepSeek V4 Flash）来处理具体任务。

## 委派原则

1. **任务专业化**：将具体、明确的任务委派给专门的子代理
2. **资源优化**：让主模型专注于高层次决策和协调，子代理处理执行细节
3. **效率提升**：通过并行处理多个子任务来加速整体工作流程

## 委派策略

### 适合委派的任务类型

1. **代码探索和搜索**：使用 `explore` 代理进行文件搜索、代码分析
2. **具体实现任务**：使用 `general` 代理编写代码、修复bug
3. **研究性任务**：使用子代理进行文档查阅、API研究
4. **重复性工作**：测试运行、构建验证等

### 委派时机

- 当任务可以分解为独立子任务时
- 当需要专门领域知识时
- 当主模型需要专注于整体协调时
- 当子代理有更适合的模型特性时

## 委派模式

### 直接委派
```
使用任务工具委派具体任务给子代理
```

### 并行委派
```
同时委派多个独立任务给不同的子代理
```

### 渐进式委派
```
先委派探索性任务，根据结果再委派实现任务
```

## 最佳实践

1. **清晰的任务描述**：为子代理提供明确、具体的任务描述
2. **适当的上下文**：提供足够的背景信息，但避免信息过载
3. **结果整合**：主模型负责整合子代理的结果并做出最终决策
4. **错误处理**：为子代理任务设置合理的超时和错误处理机制

## 示例用法

### 示例1：代码重构任务
主模型识别需要重构的代码区域，然后委派给 `general` 代理进行具体重构实现。

### 示例2：探索性任务
主模型需要了解项目结构，委派给 `explore` 代理进行文件搜索和分析。

### 示例3：多步骤任务
主模型将复杂任务分解为多个子任务，分别委派给不同的子代理并行处理。

## 配置建议

在 `opencode.json` 中确保：
- 主模型使用 `xiaomi/mimo-v2.5-pro`
- 子代理使用 `deepseek/deepseek-v4-flash`
- 为不同代理设置适当的权限和模式

## 注意事项

1. 委派并不意味着完全放手，主模型仍需监督和协调
2. 对于关键决策，主模型应保持控制权
3. 根据任务复杂度和重要性决定是否委派
4. 定期评估委派效果，调整委派策略
