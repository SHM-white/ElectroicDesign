# 子代理协调器

此技能帮助主模型有效地协调多个子代理，实现并行处理和任务优化分配。

## 协调模式

### 1. 并行任务分配
将多个独立任务同时分配给不同的子代理：

```
任务A → 子代理1 (探索代理)
任务B → 子代理2 (通用代理)  
任务C → 子代理3 (通用代理)
```

### 2. 流水线处理
将复杂任务分解为多个阶段，由不同子代理依次处理：

```
阶段1: 探索代理分析需求
阶段2: 通用代理实现功能
阶段3: 探索代理验证结果
```

### 3. 专家模式
根据任务类型选择最适合的子代理：

- **探索代理**：代码搜索、结构分析、文档查找
- **通用代理**：代码实现、测试编写、bug修复

## 协调策略

### 任务分解原则
1. **独立性**：确保子任务之间没有依赖关系
2. **明确性**：为每个子代理提供清晰的任务描述
3. **完整性**：确保所有子任务覆盖完整需求

### 结果整合策略
1. **收集结果**：等待所有子代理完成
2. **验证一致性**：检查结果是否相互冲突
3. **整合输出**：将结果合并为最终交付物

## 最佳实践

### 任务分配
- 根据子代理的专长分配任务
- 为每个任务设定合理的优先级
- 提供足够的上下文信息

### 进度监控
- 跟踪每个子代理的执行状态
- 及时处理执行过程中的问题
- 根据需要调整任务分配

### 错误处理
- 为子代理任务设置超时机制
- 准备备选方案应对失败情况
- 记录错误信息用于调试

## 示例用法

### 示例1：代码重构项目
```
1. 探索代理：分析现有代码结构
2. 通用代理A：重构核心模块
3. 通用代理B：更新测试用例
4. 探索代理：验证重构结果
```

### 示例2：功能开发
```
1. 探索代理：研究相关API文档
2. 通用代理：实现核心功能
3. 通用代理：编写单元测试
4. 探索代理：进行集成测试
```

### 示例3：问题调试
```
1. 探索代理：收集错误日志
2. 通用代理：分析根本原因
3. 通用代理：实现修复方案
4. 探索代理：验证修复效果
```

## 配置建议

### 代理设置
- 主模型使用 `xiaomi/mimo-v2.5-pro`
- 探索代理使用 `deepseek/deepseek-v4-flash`（只读权限）
- 通用代理使用 `deepseek/deepseek-v4-flash`（读写权限）

### 权限配置
- 探索代理：只读访问，禁止修改文件
- 通用代理：读写访问，允许执行命令
- 主模型：完全访问权限

## 性能优化

### 并行度控制
- 根据系统资源调整并行任务数量
- 避免过度并行导致资源竞争
- 监控执行效率，动态调整策略

### 缓存机制
- 缓存常用搜索结果
- 重用已有的分析结果
- 避免重复计算

### 负载均衡
- 根据子代理负载分配任务
- 避免单个子代理过载
- 动态调整任务分配策略
